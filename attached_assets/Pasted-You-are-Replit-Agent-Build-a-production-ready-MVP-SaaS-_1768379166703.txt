You are Replit Agent. Build a production-ready MVP SaaS called “Ops Copilot” (AI-driven intake → process blueprint → automation templates → ROI dashboard).

GOAL (MVP)
A multi-tenant web app where an SMB can:
1) Create an org + invite users
2) Run a guided Intake Wizard (pain points + uploads)
3) Generate a “Process Blueprint” (LLM-generated structured process map + bottlenecks + automation backlog)
4) Browse and configure 1–2 Automation Templates (initially “Email-to-Task Triage” and “Lead Follow-up”)
5) Run a simulated “Automation Run” (no real external integrations needed yet) and see Run Logs
6) See an ROI Dashboard (hours saved, cycle time improvement estimate, confidence score)

NON-GOALS (for MVP)
- No real OAuth integrations yet (build the data model + UI placeholders + “Connect” buttons that store “pending” connection records)
- No complex workflow engine (use a simple job runner + mock steps)
- No enterprise SSO

TECH STACK (use exactly this)
- Next.js 14 (App Router) + TypeScript
- Tailwind CSS
- Prisma ORM
- Postgres database
- Auth: NextAuth (Credentials + magic link optional) OR Clerk. Choose NextAuth for simplicity.
- Background jobs: BullMQ + Redis (if Redis is too heavy in Replit, fall back to in-process queue with setTimeout, but keep BullMQ interface)
- LLM: OpenAI API (server-side). Use an abstraction so it’s easy to swap models.
- File storage: local filesystem for MVP (uploads folder). Keep interface compatible with S3 later.

DATA MODEL (Prisma)
Multi-tenant:
- User (id, name, email, passwordHash, createdAt)
- Org (id, name, createdAt)
- OrgMember (id, orgId, userId, role: OWNER|ADMIN|MEMBER)
- Intake (id, orgId, createdByUserId, title, status: DRAFT|SUBMITTED|PROCESSED, painArea enum: SALES|SUPPORT|FINANCE|OPS, answers JSON, createdAt)
- Upload (id, orgId, intakeId?, filename, path, mime, size, createdAt)
- Blueprint (id, orgId, intakeId, title, summary, processJson JSON, bottlenecksJson JSON, backlogJson JSON, createdAt)
- AutomationTemplate (id, key unique, name, description, configSchema JSON)

- Run (id, orgId, automationConfigId, status: QUEUED|RUNNING|SUCCESS|FAILED, startedAt, endedAt, statsJson JSON)
- RunLog (id, runId, ts, level: INFO|WARN|ERROR, message, metaJson JSON)
- MetricSnapshot (id, orgId, periodStart, periodEnd, hoursSaved, cycleTimeReductionPct, confidenceScore, createdAt)

INTAKE WIZARD (MVP FLOW)
Steps:
1) Choose pain area (Sales/Support/Finance/Ops)
2) Describe the problem (free text)
3) Current tools (checkboxes + text)
4) Volume metrics (e.g., emails/day, leads/week, invoices/month)
5) Upload relevant files (optional)
6) Confirm + Submit

On submit:
- status = SUBMITTED
- enqueue job: PROCESS_INTAKE(intakeId)

LLM BLUEPRINT GENERATION
Implement /lib/llm.ts:
- function generateBlueprint(input): returns structured JSON:
  {
    title,
    summary,
    process: [{ step, ownerRole, tools, input, output, avgTimeMin }],
    bottlenecks: [{ type, description, impact, evidence }],
    backlog: [{ item, type: AUTOMATION|SOP|DATA_FIX, expectedImpact, effort: S|M|L, priorityScore }]
  }

Prompting requirements:
- Deterministic-ish: use low temperature.
- Must output valid JSON only. Validate and repair if needed.
- If OpenAI key missing, fall back to a deterministic mock blueprint generator (so app works out of the box).

Job worker:
- Takes Intake + uploaded file names (do NOT parse file contents in MVP)
- Generates Blueprint and stores it.

ROI DASHBOARD (MVP)

- Show:

  - Cycle time reduction % (simple heuristic)
  - Confidence score (0–100): based on #runs, exception rate
